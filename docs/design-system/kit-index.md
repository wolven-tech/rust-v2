### LinkButton

`rv2_ui::LinkButton` · module `primitives` · intent: Go somewhere, as a CTA · emits `a`

An anchor styled as a button.

A call-to-action that navigates is an `<a>`, not a `<button>` — it must be
middle-clickable, openable in a new tab, and crawlable. This crate takes
`dioxus` without the router feature so the kit stays renderer-agnostic;
callers pass a plain `href` and wrap with `Link` themselves if they want
client-side routing.

| Prop | Type | Default | Notes |
|---|---|---|---|
| `href` | `String` | required |  |
| `variant` | `Variant` | `Default` |  |
| `size` | `Size` | `Default` |  |
| `class` | `String` | `Default` |  |
| `external` | `bool` | `false` | Set for links leaving the site; adds `rel="noopener noreferrer"`, without which the opened page can reach back through `window.opener`. |
| `download` | `Option<String>` | `Default` | The `download` filename, for a link that saves a file rather than opening a page. |
| `disabled` | `bool` | `false` | Renders the link with no `href`. `pointer-events: none` alone, which is what the hand-written version did, stops a mouse and nothing else: the link stays in the tab order and Enter still follows it. An anchor without an `href` is not focusable and cannot be followed at all, which is what "disabled" has to mean. |
| `children` | `Element` | — |  |

### Checkbox

`rv2_ui::Checkbox` · module `form` · intent: Toggle a facet · emits native controls

A labelled checkbox, optionally carrying a count of what it would match.

The count is the reason this is a component rather than a bare `input`. A
filter rail that shows a facet with no count forces the reader to click it
to discover it matches nothing, and a rail whose zero-count options vanish
makes the list flicker as selections change. Showing the number, and dimming
rather than hiding a zero, keeps the set of options stable while still
saying which ones are worth choosing.

| Prop | Type | Default | Notes |
|---|---|---|---|
| `label` | `String` | required |  |
| `checked` | `bool` | required |  |
| `count` | `Option<usize>` | `Default` | How many records this option would match right now. Rendered to the right, dimmed when nought. |
| `basis` | `Option<String>` | `Default` | Where the value came from, when it was derived rather than recorded — "headcount band, not revenue". Shown under the label and bound as the box's description, so the reader can disagree with a judgement the data did not actually make. A `title` would hide it from touch and most screen readers. |
| `disabled` | `bool` | `false` |  |
| `onchange` | `EventHandler<bool>` | required |  |

### Bar

`rv2_ui::Bar` · module `primitives` · intent: Signal · emits `span`/`div`

One labelled row of a proportional bar chart.

The number is always rendered as text and the bar sits behind it. That
order is deliberate: the bar is the thing a reader scans and the number is
the thing they act on, so the number can never be the part that got
estimated from a pixel width. A reader with the bar hidden — a screen
reader, a high-contrast mode, a printout — loses nothing.

`of` is the largest count in the set rather than the total, because the
question these answer is "which of these is biggest" far more often than
"what share of the whole is this". A bar scaled to a total where one bucket

### Tone

enum in `typography`

Body text tone.

The tone owns the paragraph's colour, and a `class` passed to [`Text`]
cannot override it reliably: two colour utilities on one element resolve by
stylesheet order, not by which was written last. So a paragraph that needs
a different colour needs a tone, not a class (UI5). `OnInk` is the one that
was missing — secondary text on an ink-filled plate, which `apps/web` had
been writing by hand because `Text` kept painting it dark-on-dark.

- `Default`
- `Muted`
- `Small`
- `Lead`
- `OnInk`

### Width

enum in `layout`

Horizontal content width.

`Prose` is deliberately narrower than `Default`: long-form reading breaks
down past roughly 75 characters per line, so guide pages want a tighter
measure than a three-column card grid does.

`Narrow` is a single form — sign-in and the like — where a wider column only
stretches the inputs. `Dense` is a data screen that wants every column it can
get: a filter rail beside a results table. It also takes the smaller gutter,
because on such a screen the gutter is width the data does not get.

- `Narrow`
- `Prose`
- `Default`
- `Wide`
- `Dense`
